# ชั้นหนังสือ 3D บน Hero หน้าแรก — Design Spec

วันที่: 2026-11-04 · สาขา: `feat/home-3d-shelf` · สถานะ: รอตรวจ spec

## เป้าหมาย

เปลี่ยนชั้นหนังสือ 3 เล่มบน hero เป็นชั้น 3D ต่อเนื่องที่แสดงงานวิจัยจริง ให้ผู้เข้าชมเลื่อนดูและดึงเล่มออกมาพิจารณาได้ โดยการค้นหายังเป็นงานหลักของหน้า

**ถือว่าสำเร็จเมื่อ**

- เลื่อนชั้นได้ด้วยการลาก ล้อเมาส์แนวนอน ปุ่มบนจอ ปุ่มลูกศร และแถบตำแหน่ง
- กดเล่มแล้วหมุนและซูมดูได้ พร้อมข้อมูลและลิงก์ไปหน้างานวิจัย
- ช่องค้นหาและลิงก์ทุกจุดใช้งานได้ก่อน 3D โหลดเสร็จ และใช้ได้แม้ 3D โหลดไม่ได้
- ล้อเมาส์แนวตั้งและการปัดแนวตั้งบนชั้นยังเลื่อนหน้าเว็บตามปกติ
- ไม่เกิด layout shift ตอนสลับจาก fallback เป็น 3D

**ไม่อยู่ในขอบเขต**

- การใช้ Mint MCP หรือโมเดลสำเร็จรูป (ตัดสินใจแล้ว: สร้างหนังสือด้วยโค้ด)
- การนำชื่อเล่ม ลาย ข้อความ หรือเลย์เอาต์ของ The Complete Shelf มาใช้ ใช้เป็นแรงบันดาลใจด้านการโต้ตอบเท่านั้น
- การ pan ในโหมดดูเล่ม เก็บสถานะใน URL และ analytics ของชั้น

## ข้อเท็จจริงที่ตรวจแล้ว

| เรื่อง | ผลตรวจ | ผลต่อการออกแบบ |
|---|---|---|
| ข้อมูลหน้าแรก | `HOMEPAGE_RESEARCH_SELECT` ไม่มี `abstract` และ mapper คืนค่าว่าง | ต้องมี query เฉพาะของชั้น |
| จำนวนเล่ม | `homepageLatestCount` ตั้งได้ 1–24 ค่าเริ่มต้น 8 | จำนวนเล่มบนชั้นต้องไม่ผูกกับค่านี้ |
| CORS | Supabase Storage production ตอบ `Access-Control-Allow-Origin: *` (ทดสอบกับ bucket `site-assets`) | ไม่ได้พึ่ง CORS เพราะโหลดผ่าน optimizer ตามหัวข้อ Texture |
| CSP | ไม่พบ `Content-Security-Policy` ของหน้าเว็บใน `middleware.ts`, `vercel.json`, `next.config.ts`, `lib/` | ไม่ต้องแก้ CSP |
| ฟอนต์ | ไทยใช้ `--font-noto-thai` ลาวใช้ `--font-noto-lao` แยกกัน | canvas ต้องระบุทั้งสองฟอนต์ |
| Android | Capacitor ชี้ไป production URL | ได้ฟีเจอร์นี้พร้อมเว็บ ต้องผ่านเงื่อนไขอุปกรณ์เดียวกัน |

## เลย์เอาต์

- ส่วนบนของ hero: หัวข้อ คำอธิบาย ช่องค้นหา ทางลัดหมวดหมู่ สถิติ คงเนื้อหาเดิม พื้นยังเป็น `brand-900`
- ส่วนล่างของ hero: แถบชั้นเต็มความกว้าง ความสูงคงที่ `clamp(280px, 38vh, 420px)` และ 260px บนจอต่ำกว่า 640px กันพื้นที่ไว้ตั้งแต่ HTML แรก
- ถ้ามีหนังสือน้อยกว่า 2 เล่ม ไม่แสดงแถบชั้น (ตรงกับพฤติกรรมเดิม)
- โทนสี: ชั้นไม้วอลนัตและปกผ้าสีหม่น 6 สี บนพื้นสีแบรนด์ แสงอุ่น
- ใช้ `titleTh` เป็นชื่อเรื่องเหมือน hero ปัจจุบัน ส่วนชื่อหมวดหมู่ใช้ `getCategoryName` ตาม locale

## สถาปัตยกรรม

```
app/[locale]/page.tsx            ดึง getShelfResearch(SHELF_SIZE) รอบเดียวกับ latest/popular
  └─ components/home/Hero.tsx    server component ส่ง books ให้ HeroShelf
       └─ components/home/shelf/
            HeroShelf.tsx        client: รายการลิงก์จริง + ตรวจอุปกรณ์ + dynamic import
            ShelfControls.tsx    ปุ่ม แถบตำแหน่ง ข้อความ aria-live
            ShelfInspector.tsx   dialog แสดงข้อมูลเล่ม
            shelfScene.ts        Three.js: scene กล้อง แสง เรนเดอร์ เก็บกวาด
            bookGeometry.ts      สร้าง mesh หนังสือและชั้น
            bookTextures.ts      วาดปกและสันด้วย canvas โหลดปกจริง
            shelfMath.ts         ตรรกะล้วน ไม่แตะ DOM หรือ WebGL
            capability.ts        ตัดสินว่าควรเปิด 3D ไหม
            types.ts             ShelfBook และ interface ระหว่างส่วน
```

ขอบเขตของแต่ละส่วน:

- `shelfScene.ts` เปิด API ขนาดเล็กให้ React: `createShelfScene(canvas, books, callbacks)` คืน `{ goTo, inspect, closeInspect, resize, dispose }` และแจ้งกลับผ่าน `onSelect`, `onOpen`, `onError` React ไม่แตะ object ของ Three.js
- `shelfMath.ts` รับผิดชอบตำแหน่งเล่ม การ snap ความเฉื่อย ขอบเขตการเลื่อน และ seed จาก slug
- `three` import เฉพาะในไฟล์ที่โหลดผ่าน `dynamic import` ห้ามเข้า bundle แรกของหน้าแรก

## ข้อมูล

เพิ่ม `getShelfResearch(limit)` ใน `lib/data/research.server.ts`:

- ใช้ `createPublicClient()` และ `unstable_cache` แท็ก `PUBLIC_RESEARCH_TAG`, `PUBLIC_HOME_TAG` เหมือน `getLatestResearch` จึงเห็นเฉพาะงานที่ guest เห็นได้ตาม RLS
- select เหมือน `HOMEPAGE_RESEARCH_SELECT` และเพิ่ม `abstract` โดยไม่แก้ query เดิม
- ตัดบทคัดย่อฝั่งเซิร์ฟเวอร์เหลือไม่เกิน 280 ตัวอักษร เพื่อคุมขนาด payload
- มี fallback mock เมื่อ `isSupabaseConfigured()` เป็นเท็จ
- `SHELF_SIZE = 16`
- `page.tsx` เลิกใช้ `latest.slice(0, 3)` และ prop `shelf` กับ `allCategories` ของ `Hero` เปลี่ยนเป็น `books: ShelfBook[]` ที่แปลงฝั่งเซิร์ฟเวอร์แล้ว

```ts
interface ShelfBook {
  id: string;            // slug ใช้กับ /research/[id]
  title: string;
  authors: string;
  year: number;
  abstract: string;
  categoryName: string;
  coverUrl: string | null; // null เมื่อ hasRealCoverImage เป็นเท็จ
}
```

## ตัวหนังสือและ Texture

- หนังสือแต่ละเล่มประกอบด้วยปกหน้า ปกหลัง สัน และเนื้อกระดาษ สีผ้า ความสูง ความกว้าง และความหนามาจาก seed ของ slug จึงคงที่ทุกครั้งที่โหลด
- สันหนังสือวาดด้วย canvas หมุนข้อความทั้งบรรทัด 90° ไม่เรียงทีละตัว เพื่อให้สระและวรรณยุกต์ไทย/ลาวอยู่ถูกตำแหน่ง ชื่อยาวตัดด้วย `…` ตามความกว้างที่วัดได้
- ก่อนวาดต้องรอ `document.fonts.load()` ของทั้งสองฟอนต์ และอ่านชื่อฟอนต์จริงจาก CSS variable เพราะ `next/font` สร้างชื่อที่ hash
- ปกจริงโหลดผ่าน `/_next/image` (same-origin ย่อขนาดแล้ว) จึงไม่ขึ้นกับ CORS ของต้นทาง ถ้าโหลดไม่ได้ให้ใช้ปกเรียงพิมพ์แทน
- ปกเรียงพิมพ์วาดด้วย canvas ตามโครงเดียวกับ `CategoryCover`: หมวดหมู่ ชื่อเรื่อง ผู้วิจัย ปี
- สันโหลดทันที ปกหน้าโหลดเฉพาะเล่มใกล้ตำแหน่งปัจจุบัน ±3 เล่ม ขนาดสัน 128×1024 ปก 512×720 และเล่มที่เปิดดูใช้ 1024×1440

## การโต้ตอบ

- **ลาก:** Pointer Events แนวนอน มีความเฉื่อย แล้ว snap เข้าเล่มใกล้ที่สุด ตั้ง `touch-action: pan-y` ให้การปัดแนวตั้งเลื่อนหน้า
- **ล้อเมาส์:** ตอบสนองเมื่อ `|deltaX| > |deltaY|` เท่านั้น นอกนั้นไม่เรียก `preventDefault`
- **คีย์บอร์ด:** ซ้าย/ขวาเลื่อนเล่ม Enter เปิดดู Esc ปิด ทำงานเมื่อโฟกัสอยู่ในแถบชั้น
- **เลือกเล่ม:** เล่มที่เลือกหันปกออกมาด้านหน้าชั้น เล่มอื่นคงเห็นเป็นสัน ถ้าลากเกิน 6px ไม่นับเป็นการคลิก
- **ดูเล่ม:** แถบชั้นขยายเป็น `role="dialog"` เต็มจอ ล็อกการเลื่อนหน้า เปิด OrbitControls แบบหมุนและซูม ปิด pan มีข้อมูลด้านขวาบนเดสก์ท็อป และเป็น bottom sheet บนมือถือ ปิดแล้วคืนโฟกัสไปที่เดิม
- ล้อเมาส์ซูมได้เฉพาะในโหมดดูเล่ม

## ประสิทธิภาพ

- เริ่มโหลด 3D หลัง `load` ผ่าน `requestIdleCallback` เมื่อแถบชั้นใกล้เข้าจอ
- เรนเดอร์เมื่อมีการเปลี่ยนแปลงเท่านั้น ไม่วนเฟรมตลอด และหยุดเมื่อแถบพ้นจอหรือแท็บถูกซ่อน
- จำกัด `devicePixelRatio` ที่ 2 บนเดสก์ท็อป และ 1.5 บนมือถือ
- ไม่ใช้ shadow map แบบ real-time ใช้เงาระนาบแบบเบาแทน
- `dispose()` เก็บกวาด geometry, material, texture และ renderer ทั้งหมดเมื่อ unmount

งบประมาณ: เพิ่ม JS ใน bundle แรกของหน้าแรกไม่เกิน 10 KB gzip ส่วน chunk 3D ต้องวัดด้วย `ANALYZE=true` และรายงานตัวเลขจริง

## Fallback และการเข้าถึง

`HeroShelf` เรนเดอร์ `<ul>` ลิงก์จริงของทุกเล่มจากเซิร์ฟเวอร์เสมอ รายการนี้เป็นทั้ง fallback และทางเข้าของ screen reader

- ไม่เปิด 3D (ใช้รายการเลื่อนแนวนอนแทน) เมื่อ: ไม่มี WebGL2, `saveData` เปิดอยู่, `deviceMemory` ต่ำกว่า 4 เมื่อเบราว์เซอร์รายงานค่านี้, หรือโหลด chunk ไม่สำเร็จ
- `webglcontextlost` หรือ error ขณะสร้าง scene: `dispose()` แล้วกลับไปใช้รายการ ไม่แสดง error ให้ผู้ใช้
- เมื่อ 3D พร้อม รายการจะซ่อนแบบ `sr-only` แต่ยังโฟกัสได้ และเมื่อลิงก์ได้รับโฟกัส ชั้นจะเลื่อนไปเล่มนั้น
- canvas ตั้ง `aria-hidden` การเปลี่ยนเล่มประกาศผ่าน `aria-live="polite"`
- `prefers-reduced-motion`: เปลี่ยนเล่มทันที ไม่มีความเฉื่อยและแอนิเมชันดึงเล่ม ส่วนการหมุนที่ผู้ใช้ลากเองยังทำได้
- ปุ่มทุกปุ่มสูงอย่างน้อย 44px และมีข้อความใน `messages/{th,en,lo,vi}.json` ใต้คีย์ `home.shelf*`

## การทดสอบ

- **Vitest:** `shelfMath` (ตำแหน่ง snap ขอบเขต seed คงที่), `capability`, การตัด abstract และการแปลงเป็น `ShelfBook`
- **Playwright:** เลื่อนด้วยปุ่มและคีย์บอร์ด เปิดและปิดโหมดดูเล่ม คืนโฟกัส ล้อเมาส์แนวตั้งยังเลื่อนหน้า ลิงก์ไปหน้างานวิจัย
- **Fallback:** ปิด WebGL ใน Playwright แล้วยืนยันว่ารายการลิงก์ใช้งานได้
- **axe:** รันบนหน้าแรกทั้งสถานะปกติและโหมดดูเล่ม
- **ตรวจด้วยตา:** ข้อความไทยและลาวบนสันและปก ขนาด 375px, 768px และเดสก์ท็อป ทั้งธีมสว่างและมืด

Android WebView จะตรวจหลัง deploy เพราะแอปชี้ไป production URL

## ความเสี่ยงที่เหลือ

- ชื่อภาษาไทยยาวมากบนสันแคบอาจอ่านยาก แผนรับมือคือตัดด้วย `…` และแสดงชื่อเต็มเมื่อเลือกเล่ม
- `deviceMemory` ไม่มีใน Safari และ Firefox อุปกรณ์เหล่านี้จึงตัดสินจาก WebGL2 และ `saveData` เท่านั้น
- ไฟล์ที่ค้างอยู่ใน working tree ไม่เกี่ยวกับงานนี้ ต้อง stage เฉพาะไฟล์ของงานนี้ทุกครั้ง
